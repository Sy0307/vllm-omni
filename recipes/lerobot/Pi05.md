# Pi0.5 VLA

> Vision-Language-Action policy serving over the OpenPI realtime websocket

## Summary

- Vendor: Physical Intelligence (checkpoint redistributed by LeRobot)
- Model: `lerobot/pi05_base`
- Task: multi-camera images + language instruction + robot proprioceptive state
  -> continuous action chunk `[action_horizon, action_dim] = [50, 32]`
- Mode: Online serving via `/v1/realtime/robot/openpi`
- Maintainer: Community

## Runtime Shape

`Pi05Pipeline` is a single diffusion stage. It follows the same OpenPI serving
surface as `Pi0Pipeline`, but the model input differs:

- traditional VLM inference decodes text tokens from image/text context;
- pi0/pi0.5 VLA inference denoises continuous robot actions, so the response is
  `multimodal_output["actions"]`, not generated text;
- pi0 passes robot state as a separate suffix tensor to the action expert;
- pi0.5 serializes normalized/discretized state into the prompt, and the action
  expert suffix contains action tokens only.

## Command

```bash
vllm serve lerobot/pi05_base \
  --omni \
  --host 0.0.0.0 --port 8000 \
  --served-model-name pi05 \
  --deploy-config vllm_omni/deploy/pi05.yaml \
  --enforce-eager --disable-log-stats
```

The deploy config declares `Pi05Pipeline`, `float32`, `max_num_seqs: 1`, and the
OpenPI handshake metadata: 3 cameras, `joint_position`, action horizon 50,
action dim 32.

## Verification

```bash
python examples/online_serving/pi05/openpi_client.py \
  --host 127.0.0.1 --port 8000 \
  --prompt "pick up the red block and place it in the bin"
```

Expected output is a finite `[50, 32]` action array. Replace the example
cameras/state with real robot observations for deployment.
